## What it does

`src/@@package_name@@/synthetic.py` derives a bounded, reproducible set of rows
from a SHA-256 seed. `src/@@package_name@@/main.py` writes them as CSV and prints
a per-category summary. The same values are produced on every run, on every
machine. No real or production data is read.

## Run the checks

Use [uv](https://docs.astral.sh/uv/). The project declares no third-party
dependencies, so both commands work without network access:

```bash
uv sync --locked
uv run python -m unittest discover --start-directory tests --top-level-directory .
```

Write output locally:

```bash
uv run python src/@@package_name@@/main.py --rows 10 --output ./local-output.csv
```

## Before you deploy anything

`databricks.yml` declares the bundle and target. `resources/synthetic_job.yml`
declares one job with a single-node cluster, one concurrent run and an explicit
timeout. The `spark_version` and `node_type_id` bundle variables have **no
defaults**: supply values you have checked for availability and cost in your own
workspace. There is no schedule; the job runs only when it is invoked.

`.github/workflows/ci.yml` runs the locked install, lint and offline tests with
no workspace credentials. `.github/workflows/deploy.yml` is a manual-dispatch
skeleton that deliberately fails before any bundle command until a repository
administrator configures a scoped identity and sets the `DEPLOYMENT_ENABLED`
repository variable. Anyone who can dispatch or edit that workflow can bypass
the control plane's approvals; treat it as a single-administrator sandbox until
an enforced deployment design is in place.

## Provenance

The control plane records the template name, version and content digest, the
generation parameters, and the SHA-256 digest of the archive this project was
extracted from. Editing these files locally does not change that record, and the
recorded digest no longer describes your working copy once you do.
